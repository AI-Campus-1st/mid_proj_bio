## 2. 대시보드 필터 점검 (2026-11-18)

**방법:** Streamlit 테스트 도구(`streamlit.testing.v1.AppTest`)로 7개 화면 함수를 필터 조합 17개(기본 1 + 16)로 실행해, 예외·오류 상자가 없는지와 지표·차트 데이터·표·안내 문구·Q&A 범위 문구가 기본값과 달라지는지 비교했다. API는 부르지 않는다.

```bash
python tests/check_dashboard_filters.py --out 결과.md
```

필터 조합: 기간 1개월(2026-09) · 기간 1일(2025-05-22) · 기업 1개 ×5 · 카테고리 1개 ×6 · 기업 2개 + 카테고리 2개 · 기업 0개 · 카테고리 0개.

**결과:** 화면 실행 119회, **오류 0건**. 변화 없음 7건은 모두 S6 공시 Q&A의 카테고리 조합으로, S6은 카테고리를 적용하지 않는 설계다(UI_SPECIFICATION 4-3절, U4 — 질문 범위는 기간·기업만).

| 화면 | 필터 반영 | 예 (기본 → 필터) |
|---|---|---|
| S0 요약 | 카드 태그로 거르기, 분석 기사·연결 공시 | 기업 1개(프레스티지) → 카드 기회 1·위험 1, 분석 기사 37건 |
| S1 이슈·트렌드 | 기사량·급증·대표 기사 | 카테고리 모달리티 → 기사 1,034건, 급증 45회 |
| S2 규제·정책 | 감성 지표·추이·타임라인 | 기업 1개(프레스티지) → 기회 9·위험 0·중립 7 |
| S3 기술·생산 | 모달리티 기사·증설 공시 | 카테고리 모달리티 → 모달리티 기사 1,028건 |
| S4 기업 비교 | 주요 공시 분류 건수 | 기업 1개(프레스티지) → 수주 공시 15건 |
| S5 뉴스-공시 연계 | 연결 기사·공시·이슈 | 카테고리 수주 → 연결 기사 576건, 공시 129건 |
| S6 공시 Q&A | 질문 범위(기간·기업) 문구 | 기업 1개 → "기업: 프레스티지바이오로직스" |

**발견한 문제와 처리**

| # | 문제 | 처리 |
|---|---|---|
| 1 | 연결 데이터 거르기(`filter_links`)가 결과 0행일 때 열까지 없는 표를 돌려줌 → S0 "연결 공시"가 "—"로 표시 | 고침 (`dashboard/core/data.py`, 거르기 조건을 bool 로 변환) |
| 2 | 기업·카테고리 0개일 때 화면마다 반응이 다름 (S1: 기사 0건인데 급증 27회 등). 명세 4-1절은 "화면은 빈 결과 상태" | S0·S1·S2·S5에 공통 안내(`ui.no_selection`) 적용. S3·S4(한주 님 화면)는 0건 지표·안내로 표시되어 그대로 둠 |
| 3 | 기업 1개를 골라도 S1 급증 수에 키워드 급증(산업 전체 기사 기준)이 포함됨 (예: 프레스티지 1개 → 급증 27회) | 명세 4-2절 규칙(키워드 급증 행은 기업으로 거르지 않음)대로라 유지. 발표에서 설명 필요 |

## 3. 화면 동작 확인 (브라우저, 2026-11-18)

| 항목 | 기준 | 결과 |
|---|---|---|
| 첫 화면 결론 {AC-01} | 1366×768에서 S0 결론이 스크롤 없이 보임 | 통과 — 결론 문장이 화면 위 354px에서 끝남 |
| 상세 보기 (L1) | 카드 태그가 필터로 들어가고 출처 화면으로 이동 | 통과 — R2 카드 → S1, 필터 2026-03-23~10-18·삼성바이오로직스·수주/경쟁 구도 |
| 이 공시에 질문 (L8) | S4·S5 공시에서 S6로 이동, 범위 표시 | 통과 — "공시 화면에서 넘어온 범위: 삼성바이오로직스 · 2026-09-10" |
| S0 검색창 → S6 | 질문이 S6에서 바로 처리됨 | 통과 (범위 밖 질문으로 확인, API 호출 없음) |
| 다크 모드 | 모든 차트 배경·글자가 다크 값 | 통과 — 차트 10개 모두 다크 값 (11-18 점검 때 배경 `#0E1117`·글자 `#E6E9EF`. 11-19 리디자인 뒤 다크 테마는 배경 `#1E3932`·글자 `#F2F0EB`, 차트 바탕은 투명으로 테마를 따름) |
| 영어 기사 번역 표시 {AC-08} | 한국어 번역 제목 + 원제목 + 원문 링크, 화면에서 번역 호출 없음 | 통과 — S2 영어 기사 424건이 `번역` 배지·한국어 제목·원제목으로 표시 (`title_ko` 797건, 번역 품질 표본 30건 검수 30/30 — AI_EVALUATION 10절) |
| 공시 Q&A 답변 {AC-16} | 근거 공시명·제출일·DART 링크 | 통과 (2026-11-18 실제 질문 1회, SK바이오사이언스 시설 투자 → 근거 [1]) |

확인하지 않은 것: 모바일 너비, 첫 접속 시 테마 판정(미결 Q15), 화면 읽기 프로그램.

## 4. 제출 전 점검 (가이드 8절, 2026-11-18)

| 항목 | 상태 | 근거 |
|---|---|---|
| 공시 수집 코드가 재실행 가능하며, 수집 기간이 뉴스와 정렬되어 있다 | ✅ | `collect/` (README "실행 순서 — 통합 DB 구축"), DB `meta` 기간 2023-10-19 ~ 2026-10-19 |
| 대시보드가 API를 직접 호출하지 않고 저장된 결과를 조회한다 | ✅ | 화면은 DB·CSV만 읽음. 예외는 공시 Q&A의 질문 시점 호출(설계 결정, NEWS_DISCLOSURE_MATCHING D4) |
| LLM 분류 결과를 표본 검수하고 정확도를 기록하였다 | ✅ | AI_EVALUATION 4절 (감성 분류 표본 180건, 85.0%) |
| 공시 Q&A 답변에 근거 공시가 표시된다 | ✅ | 3절, AI_EVALUATION 6절 |
| 필터가 모든 차트에 반영된다 | ✅ | 2절 (오류 0건, S6 카테고리 미적용은 설계) |
| 대시보드에 결론이 명시되어 있다 | ✅ | S0 결론 문장과 기회 5·위험 3 카드 (`data/processed/summary_cards.json`) |
| 키가 저장소와 발표자료에 포함되지 않는다 | 🔶 | 저장소: 통과 — 현재 파일과 전체 커밋 기록에 키 패턴 없음, `.env` 는 git 제외, `.env.example` 은 빈 값. **발표자료는 만든 뒤 다시 확인** |
| 조원 모두 전 과정의 설계 판단을 설명할 수 있다 | 🔶 | 발표 준비(Day 7)에서 확인 |
