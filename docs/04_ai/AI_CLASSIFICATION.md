## 2. T1 감성(영향) 분류

### 2-1. 왜 긍정/부정이 아니라 기회/위험인가

사용자(CDMO 사업전략 담당자)에게 필요한 것은 기사의 어조가 아니라 **CDMO 시장 전체의 파이가 커지는가 줄어드는가**이다. 어조와 영향은 자주 엇갈린다.

| 기사 | 어조 | CDMO 시장 영향 |
|---|---|---|
| "론자, 미국에 대규모 신공장 착공" | 긍정 | **기회** — 기업 국적과 무관하게 생산능력·투자 확대 |
| "삼성바이오로직스, FDA 실사에서 지적" | 부정 | **위험** |
| "미국, 수입 의약품에 100% 관세" | 부정 | **위험** — 교역 위축 |
| "미국 생물보안법 통과로 중국 CDMO 퇴출 위기" | 부정 | **중립** — 물량이 다른 나라로 옮겨 갈 뿐 시장 크기는 그대로 |
| "HLB, 간암 신약 FDA 3번째 도전…'승인 준비 완료'" | 긍정 | **중립** — 신약 허가 소식이며 위탁생산과의 관련이 드러나지 않음 |

과제의 "감성 분류"는 이 문서에서 **CDMO 시장 전체 관점의 영향 분류(기회/위험/중립)** 로 정의한다. 리포트에도 이 정의를 적는다.

> 2026-11-16 팀 합의로 기준을 "국내 CDMO 산업에 유리한가"(sentiment-v1)에서 "CDMO 시장 전체의 파이"(sentiment-v2)로 바꿨다. v1에서는 해외 경쟁사의 증설이 위험, 생물보안법이 기회였다.
>
> 같은 날 "CDMO 관련성이 약하면 중립"(규칙 2)을 판단 순서의 첫 단계로 명시했다(sentiment-v3). v2에는 "바이오 산업 전반의 성장·투자 → 기회"와 "CDMO와 관련이 약하면 → 중립"이 함께 있어 정답 라벨이 엇갈렸다.

### 2-2. 라벨 정의

| 라벨 | 정의 | 대표 사례 |
|---|---|---|
| **기회** | CDMO 시장(위탁 수요·수주·투자·생산능력)이 커지는 사건이나 흐름. 국내 기업과 해외 기업을 가리지 않는다 | 수주·계약, 증설·신공장, CDMO 신규 진출·인수합병, 실적 개선, 지원 정책(미국 내 생산 우대 포함), 인허가·실사 통과, 신규 모달리티 수요 확대 |
| **위험** | CDMO 시장이 줄거나 위축되는 사건이나 흐름 | 관세·규제에 따른 교역 위축, FDA 경고·실사 지적, 계약 해지·지연, 실적 악화·수주 부진, 감원·공장 폐쇄, 파업·사고, 소송·자금난 |
| **중립** | 시장 크기에 주는 영향을 판단할 수 없거나 단순 사실 전달 | 인사·행사·일정 안내, 기회와 위험이 비슷하게 섞인 경우, CDMO와 관련이 약한 경우(신약 개발·허가, 제품 수출·판권, CDMO 사업이 드러나지 않는 실적, 바이오 산업 전반의 성장·투자), 몫만 옮겨 가는 사건(공급망 재편 수혜 포함), 빅파마의 내재화 |

### 2-3. 판단 규칙

1. 어조가 아니라 **CDMO 시장 전체의 파이**에 미치는 영향 방향으로 판단한다.
2. **먼저 CDMO 관련성을 본다.** 제목·본문에 위탁개발·생산(CDMO·CMO) 사업이나 의약품 생산 활동(공장·증설·생산능력·생산/공급 계약·GMP·실사, CDMO 사업 진출)이 드러나지 않으면 **중립**이다. 제약·바이오 기업의 신약 개발·임상·허가, 제품 수출·판권, CDMO 사업이 드러나지 않는 실적, 바이오 산업 전반의 성장·투자·스타트업 육성, 인사·조직 소식이 여기에 해당한다. 예: "HLB, 간암 신약 FDA 3번째 도전", "삼천당, 점안제 미국 수출"은 중립.
3. 기업의 국적을 가리지 않는다. 국내든 해외든(론자, 우시, 후지필름, 캐털런트 등) CDMO의 수주·증설·성장은 **기회**, 실적 악화·감원·사고는 **위험**이다.
4. 시장 안에서 몫만 옮겨 가는 사건은 **중립**이다. 예: 생물보안법에 따른 중국 물량의 재배치, 공급망 재편으로 한국·일본·인도 등 특정 국가가 수혜를 본다는 기사.
5. 빅파마·바이오텍이 자체 공장을 짓거나 CDMO와 그 공장을 사들이는 내재화는 **중립**이다. 위탁 시장의 확대가 아니다.
6. CDMO가 다른 CDMO나 공장을 인수하는 것, CDMO 사업에 진출하려는 인수는 증설이 없어도 **기회**이다.
7. 관세는 **위험**, 미국 내 생산을 우대하는 정책과 그에 따른 미국 내 투자는 **기회**이다.
8. 행사 참가·개최 기사는 **중립**이다. 수주·착공 같은 사건이 제목의 핵심이면 그 사건으로 판단한다.
9. 기회와 위험이 함께 있으면 제목의 핵심 사건을 기준으로 한다. 그래도 정할 수 없으면 **중립**이다.
10. 제목만 있으면 제목만으로 판단한다. 추측이 필요하면 **중립 + 확신도 low** 로 둔다.
11. 영어 기사도 같은 기준이며, 이유는 한국어로 쓴다.

사람 검수자도 같은 규칙을 쓴다 ([AI_EVALUATION](AI_EVALUATION.md) 3절).

### 2-5. 프롬프트

코드: `analysis/sentiment_prompt.py` (버전 `sentiment-v3`). 프롬프트를 바꾸면 `PROMPT_VERSION` 을 올리고 아래 변경 기록에 남긴다.

**시스템 프롬프트 (요약)** — 전문은 코드에 있다.
- 역할: 글로벌 바이오 CDMO 시장을 분석하는 애널리스트
- 2-2 라벨 정의, 2-3 판단 규칙 1~11
- 출력: JSON 한 줄만

**사용자 프롬프트**

```
[기사]
언어: {ko|en}
발행일: {YYYY-MM-DD}
매체: {매체명}
제목: {제목}
본문: {본문 앞 1,500자 | (없음 — 제목만으로 판단)}
```

**출력 형식**

```json
{"label": "기회|위험|중립", "reason": "판단 이유 한 문장(한국어)", "confidence": "high|medium|low"}
```

요청에 구조화 출력(`response_format` 의 `json_schema`, 스키마 `OUTPUT_SCHEMA`)을 걸어 이 형식의 JSON만 나오게 하고, `parse_response()` 가 라벨 값·확신도 값·이유 유무를 한 번 더 검증한다. 검증에 실패하거나 모델이 거절(`refusal`)하면 라벨을 비우고 `error` 에 사유를 남긴다. 같은 명령을 다시 실행하면 실패한 기사만 다시 처리된다.

### 2-5-1. 실행 설정 — `analysis/label_sentiment.py`

| 항목 | 값 | 이유 |
|---|---|---|
| API | OpenAI Chat Completions API (동시 8건 호출) | 2026-11-16 팀 결정으로 Claude Message Batches API 에서 변경. 기사마다 한 번씩 바로 호출하고 200건마다 중간 저장한다 |
| 모델 | `gpt-6-luna` (`--model` 로 변경 가능) | 기본값(2026-11-16 팀 결정). 같은 표본에서 `gpt-6.1-sol` 85.6%, `gpt-6-luna` 84.4% 로 차이가 작고 단가는 1/20 이다 |
| effort | `low` (`--effort` 로 변경 가능) | 3개 라벨 분류라 깊은 추론이 필요 없다. 정확도가 부족하면 `medium` 과 비교 |
| max_completion_tokens | 2,048 | 추론(reasoning) 토큰이 포함되므로 JSON 길이보다 넉넉히 |
| 예상 비용 | 표본 180건 약 $0.1 | `--dry-run` 이 글자 수로 계산한 대략치(입력 $0.10, 출력 $0.50 / 1M 토큰). 전체 건수의 비용은 `--all --dry-run` 으로 확인하고, 실제 청구액은 콘솔에서 확인 |

```bash
python analysis/label_sentiment.py --sample --dry-run
```

```bash
python analysis/label_sentiment.py --sample
```

```bash
python analysis/label_sentiment.py --all
```

- `--dry-run`: 호출하지 않고 대상 건수, 예상 비용, 첫 기사의 요청 내용을 보여준다.
- 중간에 끊겨도 같은 명령을 다시 실행하면 남은 기사만 처리한다.
- 이미 같은 모델·프롬프트 버전으로 라벨이 붙은 기사는 다시 호출하지 않는다.
- API 키: 환경변수 `OPENAI_API_KEY` → `.env` 의 `OPENAI_API_KEY` 순으로 찾는다.
- Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8` 을 지정한다.

### 2-6. 결과 저장

DB(`data/db/bio_cdmo.sqlite`)는 빌드할 때마다 새로 만들어지고 `news_id` 도 다시 매겨지므로, LLM 결과는 **기사 URL을 키로 별도 파일에 저장**한다.

- 파일: `data/processed/sentiment_llm.csv`

| 컬럼 | 설명 |
|---|---|
| `url` | 기사 URL (키) |
| `label` | 기회 / 위험 / 중립 (실패 시 빈칸) |
| `reason` | 판단 이유 한 문장 |
| `confidence` | high / medium / low |
| `input_basis` | `title` / `title+body` |
| `model` | 사용한 모델 이름 |
| `prompt_version` | 예: `sentiment-v3` |
| `labeled_at` | 처리 시각 (KST) |
| `error` | 실패 사유 (`refusal:<분류>`, `max_tokens`, `parse:<내용>`, `errored:<유형>` 등). 성공이면 빈칸 |

## 3. T2 핵심 이슈 추출

> **이 절은 초안이다.** 구현(`analysis/issue_prompt.py`, `extract_issues.py`, `group_issues.py`)과 결과 파일을 보고 2026-11-17에 정리했다. 설계 의도에 대한 설명은 코드의 주석에서 가져왔으며, 구현자(hanju)의 확인을 받지 않았다. 수치는 결과 파일에서 직접 센 값이다.

### 3-1. 무엇을 뽑나

기사 한 건이 **무슨 사건을 다루는가**를 뽑는다. 감성 분류(T1)가 영향의 방향을 붙인다면, 이슈 추출은 기사를 이슈 단위로 묶을 이름을 붙인다. 규칙 기반 CDMO 키워드(6종)는 큰 주제이고, 이슈는 그 안의 개별 사건이다.

두 단계로 한다.

| 단계 | 스크립트 | 입력 | 하는 일 |
|---|---|---|---|
| ① 추출 | `analysis/extract_issues.py` | 기사 한 건 (제목 + 본문 앞부분) | 이슈 이름·이슈 유형·핵심 키워드·확신도를 붙인다 |
| ② 묶기 | `analysis/group_issues.py` | ①에서 나온 **이슈 이름 목록** (기사 본문은 넣지 않음) | 같은 사건인데 다르게 붙은 이름을 대표 이름(`issue_group`) 하나로 통일한다 |

②가 필요한 이유: ①은 기사마다 따로 호출하므로 같은 사건이 다른 이름으로 나뉜다 ("삼성바이오로직스 폴리펩타이드그룹 인수" / "삼성바이오로직스 PPG 인수").

### 3-2. 출력 항목 (① 추출)

| 항목 | 정의 | 제약 (`parse_response` 가 검사) |
|---|---|---|
| `issue` | 이슈 이름. 한국어 명사구, "주체 + 사건" 형태 | 30자 이내 |
| `issue_type` | 이슈 유형 8종 중 하나 | 목록 밖의 값이면 실패 |
| `keywords` | 이슈를 나타내는 핵심 키워드 | 1~3개, `;` 금지. 15자를 넘는 키워드는 그 키워드만 버리고, 남는 것이 없으면 실패. 저장할 때 `; ` 로 이어 붙인다 |
| `confidence` | `high` / `medium` / `low` | |

이슈 유형 — 뉴스-공시 매칭의 `event_class` 와 이어서 볼 수 있게 사건의 종류로 나눴다.

| 유형 | 내용 |
|---|---|
| 정책·규제 | 법안, 관세, 지원 정책, 정부 계획, 규제 변화 |
| 수주·계약 | 위탁생산·개발 계약, 수주, 고객 확보 |
| 증설·투자 | 공장 신설·증설, 설비 투자, 투자 유치·자금 조달 |
| M&A·진출 | 인수합병, 지분 투자, 신규 사업 진출, 분할·구조 개편 |
| 실적 | 매출·이익 발표, 실적 전망 |
| 기술·모달리티 | ADC, 세포·유전자치료제, mRNA 등 기술과 생산 방식 |
| 품질·실사 | GMP, FDA 실사·경고, 품질 문제, 인허가 |
| 기타 | 위에 해당하지 않거나 CDMO와 관련이 약한 기사 (인사, 행사, 일반 산업 동향) |

### 3-3. 이슈 이름 규칙 (프롬프트 `issue-v1`)

같은 사건을 다룬 기사에 같은 이름이 붙도록 프롬프트에 아래 규칙을 넣었다. 전체 프롬프트는 `analysis/issue_prompt.py` 의 `SYSTEM_PROMPT` 이다.

- 날짜, 금액, 수식어("대규모", "역대 최대", "본격")를 넣지 않는다.
- 기업명은 널리 쓰는 한글 이름으로 통일한다 (삼바 → 삼성바이오로직스, Lonza → 론자, WuXi → 우시).
- 정책·법안은 정식 통칭으로 쓴다 (BIOSECURE Act → 미국 생물보안법).
- **개별 계약을 구분하지 않는다.** 같은 기업의 수주 소식은 "기업명 수주"로 묶는다.
- 기사가 여러 사건을 다루면 제목이 강조하는 사건 하나를 고른다.
- 영어 기사도 이슈 이름과 키워드는 한국어로 쓴다.
- 키워드에는 "CDMO", "바이오", "기업"처럼 거의 모든 기사에 나오는 말을 넣지 않는다.
- 제목만 주어지면 제목만으로 판단하고, 기사에 없는 기업·정책 이름을 넣지 않는다.

확신도: `high` 는 제목·본문에 이슈가 분명히 드러남, `medium` 은 짐작되지만 표현이 모호함, `low` 는 제목만 있고 그것만으로는 어떤 사건인지 알기 어려움.

### 3-4. 처리 범위와 실행 설정

| 항목 | ① 추출 | ② 묶기 |
|---|---|---|
| 대상 | 감성 분류와 같은 4,727건 (2-4절. `sample_sentiment.QUERY` 를 그대로 씀) | ①의 이슈 이름 3,581개 (표기 정규화 `issue_norm` 기준) |
| 입력 | 언어, 발행일, 매체, 분류 키워드, 제목, 본문 앞 1,500자 (본문이 없으면 제목만) | 이름 120개씩 가나다순 + 이미 정해진 대표 이름 중 기사 수 많은 250개 |
| 모델 | `gpt-6-luna`, effort `low` | `gpt-6-luna`, effort `medium` (이름끼리 비교하는 일이라 한 단계 높임) |
| 호출 | 기사마다 1회, 8개 동시 | 묶음마다 1회, **차례로** (앞 묶음의 대표 이름을 뒤 묶음이 다시 쓰도록). 전체 30회 + 재실행분 1회 |
| 형식 강제 | 구조화 출력(JSON 스키마) + `parse_response` 검증 | 구조화 출력 + 검증. 응답에서 빠지거나 형식이 틀린 이름은 원래 이름을 대표 이름으로 둔다 |
| 프롬프트 버전 | `issue-v1` | `issue-group-v1` |
| 이어받기 | 같은 모델·버전으로 성공한 기사는 건너뜀, 200건마다 중간 저장 | 이미 묶인 이름은 건너뜀. 전부 다시 묶으려면 `--rebuild` |

묶기 규칙(`group_issues.py` 의 `SYSTEM_PROMPT`):

- **합친다:** 표기만 다른 경우(띄어쓰기, 약칭과 정식 이름, 영문과 한글), 같은 사건의 다른 단계나 표현("생물보안법 발의", "생물보안법 상원 통과" → "미국 생물보안법"), 같은 기업의 개별 수주 소식.
- **합치지 않는다:** 기업이 다른 경우, 같은 기업이라도 사건이 다른 경우("5공장 증설"과 "5공장 파업"), 정책이 다른 경우. 확신이 없으면 합치지 않는다.
- 대표 이름은 기존 대표 이름이나 목록에 있는 이름 중 가장 짧고 분명한 것을 고른다.
- 묶은 뒤, 공백·문장부호만 다른 대표 이름은 기사 수가 가장 많은 표기로 통일한다(`unify`).

실행:

```bash
python analysis/extract_issues.py --all --dry-run   # 건수·예상 비용 확인 (호출 없음)
python analysis/extract_issues.py --all
python analysis/group_issues.py --dry-run
python analysis/group_issues.py                      # 새 이름만. 전부 다시 묶으려면 --rebuild
python analysis/extract_issues.py --summary          # 이슈별 기사 수 (호출 없음)
```

| 제목에 쓰인 이름 그대로, 옛 이름·다른 이름으로 바꾸지 않음 (v2) | 시험 20건(v1)에서 "Fujifilm Biotechnologies"(2025년 새 이름)가 프롬프트 예시 때문에 옛 이름 "후지필름 다이오신스"로 바뀌었다 |
| ~~한글 표기가 확실할 때만 한글, 아니면 영문 그대로 (v2)~~ → v3 표기 목록으로 대체 | v1 은 작은 기업이 영문(Agappe)과 음차(아쿰스)로 섞였다. 원제목이 아래 함께 보여 영문으로 둬도 읽을 수 있고, 틀린 음차보다 낫다 |
| 원어 병기(론자(Lonza)) 하지 않음 | 원제목이 바로 아래 보여 같은 이름을 두 번 읽게 된다. 작성 가이드의 "원어 병기"를 이 이유로 바꿨다 |
| 숫자·금액은 값을 바꾸지 않고 한국어 단위로만 ($200M → 2억 달러), 원화 환산 안 함 | 환율 기준이 없다 |
| **표기 목록(`NAME_KO`, 35개)에 있는 이름은 그 한글 표기, 없으면 영문 그대로** (v3) | v2 는 한글로 쓸지를 모델이 기사마다 판단해 같은 회사가 "후지필름"/"Fujifilm" 으로 섞였다. 목록은 영어 제목 797건에 4번 이상 나온 이름 중 국내 언론 표기가 확실한 것 + 국내 5개사·대형 제약사. 표기가 불확실한 이름(Recipharm 등)은 틀린 음차보다 영문이 나아 넣지 않았다 |
| 원제목에 없는 통화·단위는 붙이지 않음 (v3) | v3 시험에서 '4.3 billion'(이탈리아 기사, 통화 없음)을 '43억 달러'로 옮겼다 |
| 검증: 한글이 있어야 하고 150자 이하 | 번역이 안 된 응답, 설명을 덧붙인 응답을 실패로 잡아 다시 호출 (원제목 최대 246자, 평균 77자) |

### 5-3. DB 재빌드 후에도 유지

`db/build_db.py` 는 뉴스를 적재할 때 `title_ko` 를 비워 둔다. 그래서 번역은 URL 키 파일(`title_ko.csv`)에 저장하고, `build_db.py` 의 `load_title_ko()` 가 빌드 때 이 파일을 읽어 다시 채운다 (2026-11-18 추가). 번역 스크립트는 실행이 끝나면 지금 DB 에도 바로 넣는다(`--apply` 로 따로도 가능). 대시보드는 다시 켜야 반영된다(읽기 함수가 캐시된다).

```
python analysis/translate_titles.py --all --dry-run   # 건수·예상 비용 (호출 없음)
python analysis/translate_titles.py --all              # 전체 실행 → 파일 저장 + DB 반영
python analysis/translate_titles.py --failed           # 실패한 기사만 다시
python analysis/translate_titles.py --summary          # 결과 요약
```

### 5-4. 실행 결과 (2026-11-18, `translate-v3`)

- 797건 모두 성공, 실패 0건. 결과 파일과 DB `news.title_ko` 모두 797건. 번역 길이 3~113자(평균 41자).
- 버전 경과: v1 시험 20건(옛 회사 이름으로 바꿈) → v2(표기가 기사마다 섞임, 600건에서 중단) → v3 시험 20건(통화 덧붙임 → 규칙 추가) → v3 전체. **v1·v2 결과는 모두 지우고 v3 로만 다시 번역했다** (결과 파일·DB 모두 v3 797건).
- 표기 목록 적용(자동 점검): 원제목에 목록 이름이 있는 237건 중 236건이 목록 표기로 옮겨졌다. 1건("Vertex/CRISPR ...")만 영문으로 남았다.
- 원제목과 똑같이 둔 4건은 제목이 이름뿐인 경우다 ("Halix", "APL", "3PBIOVIAN", "John Fowler, Pharmaceutics International, Inc. (Pii)").
- 대시보드 확인: S2 영어 기사 목록에서 "번역 준비 중" 0건, 번역 제목 + `번역` 배지 + 원제목 줄로 표시 (AC-08).

### 5-5. 한계

- 번역 품질(의미·숫자)은 아직 표본 검수하지 않았다. 표기 목록 적용만 자동으로 확인했다.
- 제목만 번역한다. 본문이 없어 문맥으로 고유명사를 확인할 수 없다.

## 6. 규칙 기반 분류와의 관계

규칙 기반 CDMO 키워드 분류(`analysis/build_cdmo_news.py`)는 **어떤 이슈인가**를, LLM 감성 분류는 **유리한가 불리한가**를 정한다. 서로 대체하지 않고, 키워드로 범위를 정한 뒤 그 안에서 LLM이 영향 방향을 붙인다.
