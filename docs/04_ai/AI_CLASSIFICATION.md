## 2. T1 감성(영향) 분류

### 2-1. 왜 긍정/부정이 아니라 기회/위험인가

사용자(CDMO 사업전략 담당자)에게 필요한 것은 기사의 어조가 아니라 **국내 CDMO 산업에 유리한가 불리한가**이다. 어조와 영향은 자주 엇갈린다.

| 기사 | 어조 | 국내 CDMO 영향 |
|---|---|---|
| "미국 생물보안법 통과로 중국 CDMO 퇴출 위기" | 부정 | **기회** — 중국 경쟁사 견제 |
| "론자, 미국에 대규모 신공장 착공" | 긍정 | **위험** — 해외 경쟁사 확장 |
| "삼성바이오로직스, FDA 실사에서 지적" | 부정 | **위험** |

과제의 "감성 분류"는 이 문서에서 **국내 CDMO 산업 관점의 영향 분류(기회/위험/중립)** 로 정의한다. 리포트에도 이 정의를 적는다.

### 2-2. 라벨 정의

| 라벨 | 정의 | 대표 사례 |
|---|---|---|
| **기회** | 국내 CDMO의 수주·매출·생산능력·경쟁력에 유리한 사건이나 흐름 | 대형 수주·계약, 증설·신공장, 실적 개선, 국내 지원 정책, 해외 경쟁사 견제 규제, 신규 모달리티 수요 확대 |
| **위험** | 국내 CDMO에 불리한 사건이나 흐름 | 관세·규제 부담, FDA 경고·실사 지적, 계약 해지·지연, 실적 악화, 해외 경쟁사의 확장·가격 공세, 소송·자금난 |
| **중립** | 영향 방향을 판단할 수 없거나 단순 사실 전달 | 인사·행사·일정 안내, 기회와 위험이 비슷하게 섞인 경우, CDMO와 관련이 약한 경우 |

### 2-3. 판단 규칙

1. 어조가 아니라 국내 CDMO 산업에 미치는 **영향 방향**으로 판단한다.
2. 해외 경쟁사(론자, 우시, 후지필름, 캐털런트 등)의 성장·증설은 **위험**, 해외 경쟁사의 악재는 **기회**이다.
3. 국내 CDMO 한 곳의 호재(수주·증설)는 **기회**, 악재는 **위험**이다.
4. 기회와 위험이 함께 있으면 제목의 핵심 사건을 기준으로 한다. 그래도 정할 수 없으면 **중립**이다.
5. 제목만 있으면 제목만으로 판단한다. 추측이 필요하면 **중립 + 확신도 low** 로 둔다.
6. 영어 기사도 같은 기준이며, 이유는 한국어로 쓴다.

사람 검수자도 같은 규칙을 쓴다 ([AI_EVALUATION](AI_EVALUATION.md) 3절).

### 2-4. 처리 범위

| 항목 | 기준 | 이유 |
|---|---|---|
| 대상 | 대표 CDMO 키워드가 있는 기사 (`news_cdmo_keywords.is_primary=1`) | CDMO와 무관한 기사(`해당 없음` 4,487건)는 기회/위험 판단의 의미가 없다 |
| 중복 | 제외 (`dup_of IS NULL`) | 같은 기사를 두 번 세지 않는다 |
| 건수 | **4,727건** (2026-11-13 빌드 기준) | 아래 표 |
| 입력 | 제목 + 본문 앞 1,500자 (본문이 없으면 제목만) | 호출량·비용을 줄이고, 기사 핵심은 대개 앞부분에 있다 |

| 출처 | 언어 | 본문 | 건수 |
|---|---|---|---|
| 제공 (`provided`) | ko | 있음 | 247 |
| 팀원 수집 (`team`) | ko | 있음 975 / 없음 7 | 982 |
| 기업명 검색 (`google_company`) | ko | 없음 | 582 |
| CDMO 검색 (`google_cdmo`) | ko | 없음 | 2,119 |
| 해외 검색 (`google_global`) | en | 없음 | 797 |

**약 74%(3,505건)는 제목만으로 판단한다.** 결과마다 판단 근거 범위(`input_basis`: `title` / `title+body`)를 저장하고, 정확도도 이 기준으로 나눠 본다.

### 2-5. 프롬프트

코드: `analysis/sentiment_prompt.py` (버전 `sentiment-v1`). 프롬프트를 바꾸면 `PROMPT_VERSION` 을 올리고 아래 변경 기록에 남긴다.

**시스템 프롬프트 (요약)** — 전문은 코드에 있다.
- 역할: 국내 바이오 CDMO 기업 사업전략팀 애널리스트
- 2-2 라벨 정의, 2-3 판단 규칙 1~6
- 출력: JSON 한 줄만

**사용자 프롬프트**

```
[기사]
언어: {ko|en}
발행일: {YYYY-MM-DD}
매체: {매체명}
제목: {제목}
본문: {본문 앞 1,500자 | (없음 — 제목만으로 판단)}
```

**출력 형식**

```json
{"label": "기회|위험|중립", "reason": "판단 이유 한 문장(한국어)", "confidence": "high|medium|low"}
```

`parse_response()` 가 JSON 형식, 라벨 값, 확신도 값, 이유 유무를 검증한다. 검증에 실패하면 같은 입력으로 재시도하고, 3회 실패하면 라벨을 비우고 실패로 기록한다.

### 2-6. 결과 저장

DB(`data/db/bio_cdmo.sqlite`)는 빌드할 때마다 새로 만들어지고 `news_id` 도 다시 매겨지므로, LLM 결과는 **기사 URL을 키로 별도 파일에 저장**한다.

- 파일: `data/processed/sentiment_llm.csv`

| 컬럼 | 설명 |
|---|---|
| `url` | 기사 URL (키) |
| `label` | 기회 / 위험 / 중립 (실패 시 빈칸) |
| `reason` | 판단 이유 한 문장 |
| `confidence` | high / medium / low |
| `input_basis` | `title` / `title+body` |
| `model` | 사용한 모델 이름 |
| `prompt_version` | 예: `sentiment-v1` |
| `labeled_at` | 처리 시각 (KST) |

DB 적재 시 `news_sentiment` 테이블로 붙인다 (`06_technical/DATABASE_SCHEMA.md` 작성 시 정의).

## 6. 규칙 기반 분류와의 관계

규칙 기반 CDMO 키워드 분류(`analysis/build_cdmo_news.py`)는 **어떤 이슈인가**를, LLM 감성 분류는 **유리한가 불리한가**를 정한다. 서로 대체하지 않고, 키워드로 범위를 정한 뒤 그 안에서 LLM이 영향 방향을 붙인다.
