## 2. T1 감성(영향) 분류

### 2-1. 왜 긍정/부정이 아니라 기회/위험인가

사용자(CDMO 사업전략 담당자)에게 필요한 것은 기사의 어조가 아니라 **CDMO 시장 전체의 파이가 커지는가 줄어드는가**이다. 어조와 영향은 자주 엇갈린다.

| 기사 | 어조 | CDMO 시장 영향 |
|---|---|---|
| "론자, 미국에 대규모 신공장 착공" | 긍정 | **기회** — 기업 국적과 무관하게 생산능력·투자 확대 |
| "삼성바이오로직스, FDA 실사에서 지적" | 부정 | **위험** |
| "미국, 수입 의약품에 100% 관세" | 부정 | **위험** — 교역 위축 |
| "미국 생물보안법 통과로 중국 CDMO 퇴출 위기" | 부정 | **중립** — 물량이 다른 나라로 옮겨 갈 뿐 시장 크기는 그대로 |
| "HLB, 간암 신약 FDA 3번째 도전…'승인 준비 완료'" | 긍정 | **중립** — 신약 허가 소식이며 위탁생산과의 관련이 드러나지 않음 |

과제의 "감성 분류"는 이 문서에서 **CDMO 시장 전체 관점의 영향 분류(기회/위험/중립)** 로 정의한다. 리포트에도 이 정의를 적는다.

> 2026-11-16 팀 합의로 기준을 "국내 CDMO 산업에 유리한가"(sentiment-v1)에서 "CDMO 시장 전체의 파이"(sentiment-v2)로 바꿨다. v1에서는 해외 경쟁사의 증설이 위험, 생물보안법이 기회였다.
>
> 같은 날 "CDMO 관련성이 약하면 중립"(규칙 2)을 판단 순서의 첫 단계로 명시했다(sentiment-v3). v2에는 "바이오 산업 전반의 성장·투자 → 기회"와 "CDMO와 관련이 약하면 → 중립"이 함께 있어 정답 라벨이 엇갈렸다.

### 2-2. 라벨 정의

| 라벨 | 정의 | 대표 사례 |
|---|---|---|
| **기회** | CDMO 시장(위탁 수요·수주·투자·생산능력)이 커지는 사건이나 흐름. 국내 기업과 해외 기업을 가리지 않는다 | 수주·계약, 증설·신공장, CDMO 신규 진출·인수합병, 실적 개선, 지원 정책(미국 내 생산 우대 포함), 인허가·실사 통과, 신규 모달리티 수요 확대 |
| **위험** | CDMO 시장이 줄거나 위축되는 사건이나 흐름 | 관세·규제에 따른 교역 위축, FDA 경고·실사 지적, 계약 해지·지연, 실적 악화·수주 부진, 감원·공장 폐쇄, 파업·사고, 소송·자금난 |
| **중립** | 시장 크기에 주는 영향을 판단할 수 없거나 단순 사실 전달 | 인사·행사·일정 안내, 기회와 위험이 비슷하게 섞인 경우, CDMO와 관련이 약한 경우(신약 개발·허가, 제품 수출·판권, CDMO 사업이 드러나지 않는 실적, 바이오 산업 전반의 성장·투자), 몫만 옮겨 가는 사건(공급망 재편 수혜 포함), 빅파마의 내재화 |

### 2-3. 판단 규칙

1. 어조가 아니라 **CDMO 시장 전체의 파이**에 미치는 영향 방향으로 판단한다.
2. **먼저 CDMO 관련성을 본다.** 제목·본문에 위탁개발·생산(CDMO·CMO) 사업이나 의약품 생산 활동(공장·증설·생산능력·생산/공급 계약·GMP·실사, CDMO 사업 진출)이 드러나지 않으면 **중립**이다. 제약·바이오 기업의 신약 개발·임상·허가, 제품 수출·판권, CDMO 사업이 드러나지 않는 실적, 바이오 산업 전반의 성장·투자·스타트업 육성, 인사·조직 소식이 여기에 해당한다. 예: "HLB, 간암 신약 FDA 3번째 도전", "삼천당, 점안제 미국 수출"은 중립.
3. 기업의 국적을 가리지 않는다. 국내든 해외든(론자, 우시, 후지필름, 캐털런트 등) CDMO의 수주·증설·성장은 **기회**, 실적 악화·감원·사고는 **위험**이다.
4. 시장 안에서 몫만 옮겨 가는 사건은 **중립**이다. 예: 생물보안법에 따른 중국 물량의 재배치, 공급망 재편으로 한국·일본·인도 등 특정 국가가 수혜를 본다는 기사.
5. 빅파마·바이오텍이 자체 공장을 짓거나 CDMO와 그 공장을 사들이는 내재화는 **중립**이다. 위탁 시장의 확대가 아니다.
6. CDMO가 다른 CDMO나 공장을 인수하는 것, CDMO 사업에 진출하려는 인수는 증설이 없어도 **기회**이다.
7. 관세는 **위험**, 미국 내 생산을 우대하는 정책과 그에 따른 미국 내 투자는 **기회**이다.
8. 행사 참가·개최 기사는 **중립**이다. 수주·착공 같은 사건이 제목의 핵심이면 그 사건으로 판단한다.
9. 기회와 위험이 함께 있으면 제목의 핵심 사건을 기준으로 한다. 그래도 정할 수 없으면 **중립**이다.
10. 제목만 있으면 제목만으로 판단한다. 추측이 필요하면 **중립 + 확신도 low** 로 둔다.
11. 영어 기사도 같은 기준이며, 이유는 한국어로 쓴다.

사람 검수자도 같은 규칙을 쓴다 ([AI_EVALUATION](AI_EVALUATION.md) 3절).

### 2-5. 프롬프트

코드: `analysis/sentiment_prompt.py` (버전 `sentiment-v3`). 프롬프트를 바꾸면 `PROMPT_VERSION` 을 올리고 아래 변경 기록에 남긴다.

**시스템 프롬프트 (요약)** — 전문은 코드에 있다.
- 역할: 글로벌 바이오 CDMO 시장을 분석하는 애널리스트
- 2-2 라벨 정의, 2-3 판단 규칙 1~11
- 출력: JSON 한 줄만

**사용자 프롬프트**

```
[기사]
언어: {ko|en}
발행일: {YYYY-MM-DD}
매체: {매체명}
제목: {제목}
본문: {본문 앞 1,500자 | (없음 — 제목만으로 판단)}
```

**출력 형식**

```json
{"label": "기회|위험|중립", "reason": "판단 이유 한 문장(한국어)", "confidence": "high|medium|low"}
```

요청에 구조화 출력(`response_format` 의 `json_schema`, 스키마 `OUTPUT_SCHEMA`)을 걸어 이 형식의 JSON만 나오게 하고, `parse_response()` 가 라벨 값·확신도 값·이유 유무를 한 번 더 검증한다. 검증에 실패하거나 모델이 거절(`refusal`)하면 라벨을 비우고 `error` 에 사유를 남긴다. 같은 명령을 다시 실행하면 실패한 기사만 다시 처리된다.

### 2-5-1. 실행 설정 — `analysis/label_sentiment.py`

| 항목 | 값 | 이유 |
|---|---|---|
| API | OpenAI Chat Completions API (동시 8건 호출) | 2026-11-16 팀 결정으로 Claude Message Batches API 에서 변경. 기사마다 한 번씩 바로 호출하고 200건마다 중간 저장한다 |
| 모델 | `gpt-6-luna` (`--model` 로 변경 가능) | 기본값(2026-11-16 팀 결정). 같은 표본에서 `gpt-6.1-sol` 85.6%, `gpt-6-luna` 84.4% 로 차이가 작고 단가는 1/20 이다 |
| effort | `low` (`--effort` 로 변경 가능) | 3개 라벨 분류라 깊은 추론이 필요 없다. 정확도가 부족하면 `medium` 과 비교 |
| max_completion_tokens | 2,048 | 추론(reasoning) 토큰이 포함되므로 JSON 길이보다 넉넉히 |
| 예상 비용 | 표본 180건 약 $0.1 | `--dry-run` 이 글자 수로 계산한 대략치(입력 $0.10, 출력 $0.50 / 1M 토큰). 전체 건수의 비용은 `--all --dry-run` 으로 확인하고, 실제 청구액은 콘솔에서 확인 |

```bash
python analysis/label_sentiment.py --sample --dry-run
```

```bash
python analysis/label_sentiment.py --sample
```

```bash
python analysis/label_sentiment.py --all
```

- `--dry-run`: 호출하지 않고 대상 건수, 예상 비용, 첫 기사의 요청 내용을 보여준다.
- 중간에 끊겨도 같은 명령을 다시 실행하면 남은 기사만 처리한다.
- 이미 같은 모델·프롬프트 버전으로 라벨이 붙은 기사는 다시 호출하지 않는다.
- API 키: 환경변수 `OPENAI_API_KEY` → `.env` 의 `OPENAI_API_KEY` 순으로 찾는다.
- Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8` 을 지정한다.

### 2-6. 결과 저장

DB(`data/db/bio_cdmo.sqlite`)는 빌드할 때마다 새로 만들어지고 `news_id` 도 다시 매겨지므로, LLM 결과는 **기사 URL을 키로 별도 파일에 저장**한다.

- 파일: `data/processed/sentiment_llm.csv`

| 컬럼 | 설명 |
|---|---|
| `url` | 기사 URL (키) |
| `label` | 기회 / 위험 / 중립 (실패 시 빈칸) |
| `reason` | 판단 이유 한 문장 |
| `confidence` | high / medium / low |
| `input_basis` | `title` / `title+body` |
| `model` | 사용한 모델 이름 |
| `prompt_version` | 예: `sentiment-v3` |
| `labeled_at` | 처리 시각 (KST) |
| `error` | 실패 사유 (`refusal:<분류>`, `max_tokens`, `parse:<내용>`, `errored:<유형>` 등). 성공이면 빈칸 |

DB 적재 시 `news_sentiment` 테이블로 붙인다 (`06_technical/DATABASE_SCHEMA.md` 작성 시 정의).

## 6. 규칙 기반 분류와의 관계

규칙 기반 CDMO 키워드 분류(`analysis/build_cdmo_news.py`)는 **어떤 이슈인가**를, LLM 감성 분류는 **유리한가 불리한가**를 정한다. 서로 대체하지 않고, 키워드로 범위를 정한 뒤 그 안에서 LLM이 영향 방향을 붙인다.
