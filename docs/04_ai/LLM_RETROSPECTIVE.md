## 1. LLM을 쓴 곳 한눈에

모든 LLM 결과는 **미리 생성해 파일로 저장**하고 대시보드는 저장된 결과만 읽는다 (가이드 6절, PRD N1·N2). 예외는 공시 Q&A로, 질문할 때 한 번 호출한다.

| 작업 | 쓰는 화면 | 모델 · 프롬프트 | 범위 | 검수 | 결과 |
|---|---|---|---|---|---|
| T1 감성(영향) 분류 — 기회/위험/중립 | S0, S1, S2 | `gpt-6-luna` (effort low) · `sentiment-v3` | 4,727건 (실패 0) | **사람 3명**, 층화 표본 180건 | 정확도 **85.0%** (층 가중 84.2%, 모두 "기회"로 찍으면 47.2%) |
| T2 핵심 이슈 추출 + 이름 묶기 | S1, S5 | `gpt-6-luna` · `issue-v1` / 묶기 `issue-group-v1` (effort medium) | 4,727건 · 이름 3,581개 → 대표 2,706개 | 사람, 층화 표본 30건 | 이슈 이름 **98.7%** · 유형 **97.4%** · 묶기 **98.7%** (층 가중) |
| T3 모달리티 태깅 (7종) | S3 | `gpt-6-luna` · `modality-v2` | 4,727건 (실패 0) | 1차 Claude 블라인드 + 사람 확인, 80건 | 태그 정밀도 **91.7%** · 재현율 **98.1%** |
| T4 영어 제목 번역 | S2 | `gpt-6-luna` · `translate-v3` | 797건 (실패 0) | 표기 목록 적용 자동 점검 | 목록 이름 236/237 적용, 사람 표본 30건 의미·숫자·이름 30/30 정확 (AI_EVALUATION 10절) |
| 공시 RAG Q&A | S6 | 임베딩 `text-embedding-3-small` + 답변 `gpt-6-luna` | 공시 864건 → 청크 36,548개 | 질문 20개 (답 있음 14, 거절해야 함 6) | 검색 **12/14**, 거절 **6/6**, 근거 일치 12/13 |
| (참고) 뉴스-공시 매칭 판정 | S5 | 매칭은 규칙 기반. LLM(Claude)은 표본 1차 판정에만 씀 | 표본 50쌍 | 사람 2명 + Claude, 19쌍 합의 | 직접·당일 같은 사건 10/15 |

**처리 범위를 정한 근거 (가이드 6절):** 기사 4,727건은 대표 CDMO 키워드가 있고 중복이 아닌 기사다. 입력은 제목 + 본문 앞 1,500자이며, 기사의 약 74%는 제목만 있다. 모델은 같은 표본에서 큰 모델(`gpt-6.1-sol`)과 비교해 정했다. 큰 모델은 정확도 85.6%, `gpt-6-luna`는 84.4%로 1.2%p 차이였는데 단가는 20배 차이였다. 그래서 모든 분류 작업에 `gpt-6-luna`를 썼다.

**비용 (가격표 기준 추정, 실제 청구액은 확인하지 않음):** 임베딩 약 $0.58, 모달리티 태깅 약 $1.7(dry-run 상한), 번역 약 $0.18(dry-run). 모든 유료 실행은 `--dry-run` 으로 건수·예상 비용을 먼저 보고, 20~50건 시험 뒤 전체를 돌렸다.

## 2. 문제와 대응

### 2-1. 정답 자체가 흔들렸다 — 라벨 기준 해석 차이

| | 내용 |
|---|---|
| 문제 | 감성 표본 180건을 세 명이 따로 라벨링했더니 Fleiss' kappa 0.337(낮은 일치). 한 명은 "기회" 대신 "중립·위험"을 훨씬 많이 붙였다. 매칭 표본도 사람 두 명의 kappa가 0.15였다 |
| 원인 | "기회"가 국내 기업 수혜인지 CDMO 시장 전체인지, 관련성이 약한 바이오 기사는 어떻게 볼지, "관련"과 "같은 사건"의 경계가 어디인지 정의되지 않았다 |
| 대응 | 감성: 기준을 "CDMO 시장 전체의 파이"로 다시 정의(v2)하고, "CDMO 관련성이 약하면 중립"을 판단 첫 단계로 넣었다(v3). 매칭: 갈린 쌍을 놓고 "같은 사건은 기사가 바로 그 공시를 다룰 때만"이라는 합의 규칙을 만든 뒤 다시 판정했다 |
| 남은 한계 | 감성 정답 22건은 **v2 LLM 결과를 본 뒤** 고쳐서, 85.0%는 독립 검수보다 높게 나왔을 수 있다. 매칭 검수 대상 19쌍은 경계 사례만 모은 것이라 일치도가 낮게 나왔다 |
| 교훈 | LLM보다 먼저 **사람의 판정 기준**을 문장으로 고정해야 정확도라는 숫자가 의미를 가진다 |

### 2-2. 규칙 하나가 오류를 옮겨 놓았다 — 감성 분류의 트레이드오프

| | 내용 |
|---|---|
| 문제 | v2에서 LLM은 정답 중립 기사를 기회로 22건 잘못 분류했다(기회 과다) |
| 대응 | v3 관련성 규칙으로 이 오류는 12건으로 줄었다 |
| 남은 한계 | 대신 정답 기회를 중립으로 둔 오류가 5건에서 12건으로 늘었다. 제목에 수주·증설이 드러나지 않는 CDMO 기사(인수, 수주전, 동맹)가 중립으로 갔다. 전체 정확도는 84.4%에서 85.0%로 거의 같다. **규칙은 오류를 없애기보다 옮긴다** |

### 2-3. 같은 입력, 다른 답 — 실행 간 편차

| | 내용 |
|---|---|
| 문제 | 같은 설정으로 감성 표본을 두 번 돌렸더니 180건 중 11건의 라벨이 달랐다 (정확도 85.6% / 85.0%) |
| 대응 | 1%p 안팎의 차이는 실행 편차로 보고, 결과 파일에는 나중 실행만 남겼다. 모든 결과에 모델·프롬프트 버전·실행 시각을 함께 저장해 어떤 실행인지 추적할 수 있게 했다 |
| 남은 한계 | 반복 실행으로 편차 크기를 정식으로 재지는 않았다 |

### 2-4. 출력 형식은 강제해도 내용 검증은 따로 필요했다

모든 LLM 호출은 구조화 출력(JSON 스키마)으로 형식을 강제하고, 파서가 한 번 더 검증한다. 형식이 틀리면 실패로 남겨 다시 호출한다. 그런데 **검증 규칙이 한국어 기준**이라 다른 입력에서 맞는 답이 실패한 경우가 세 번 있었다.

| 작업 | 실패 | 원인 | 대응 |
|---|---|---|---|
| 이슈 키워드 | 4건 | 키워드 15자 제한을 넘는 긴 행사·기관 이름 | 넘는 키워드만 버리고 기사는 살림 |
| 모달리티 근거 표현 | 영어 기사 3건 | "cell and gene therapy"(21자)가 20자 제한에 걸림 | 프롬프트는 그대로 두고 검증만 30자까지 허용 (이미 성공한 4,700여 건을 다시 돌리지 않으려고) |
| 번역 | 4건 | 제목이 "Halix", "APL"처럼 이름뿐이라 한글이 없음 | 원제목과 똑같이 돌려준 경우는 통과 |

**교훈:** 검증 규칙도 실제 데이터로 시험해야 한다. 실패를 버리지 않고 사유와 함께 남겨 둔 덕에 원인을 바로 찾았다.

### 2-5. 배경에 나온 내용까지 태그로 붙였다 — 모달리티

| | 내용 |
|---|---|
| 문제 | 시험 50건(v1)에서, 삼성바이오로직스 유상증자 기사 5건이 "기존 항체·mRNA·ADC에 이어 펩타이드까지"라는 배경 문장 때문에 태그 4개를 받았다. 기사의 사건은 펩타이드 인수 하나였다. 같은 이슈 기사가 120건이 넘어서, 히트맵의 삼성 행이 크게 부풀려질 상황이었다 |
| 대응 | v2에서 "기사 사건의 대상 모달리티만 붙인다"는 규칙을 실제 문장을 예시로 넣었다. v2 시험(99건)에서 유상증자·폴리펩타이드 인수 기사 14건 중 10건이 펩타이드만 받았고, 태그 4개를 받은 기사는 없었다. 남은 오류를 이슈 유형으로 거르는 방법도 표본에 시험했지만, 재현율이 98.1%에서 69.6%로 떨어져 쓰지 않았다 |
| 남은 한계 | 표본 검수에서 잘못 붙은 태그 5개 중 4개가 여전히 배경 태깅이었다. 특히 삼성 기사의 펩타이드가 다소 크게 잡혔을 수 있다. 화면 한계 문구와 AI_EVALUATION 8-5절에 밝히고 유지하기로 했다 |
| 교훈 | 규칙은 **문장으로만 쓰면 모델이 놓친다.** 실제 실패 문장을 예시로 넣어야 따른다 |

### 2-6. 프롬프트의 예시가 답을 끌고 갔다 — 번역

| 버전 | 문제 | 원인 | 대응 |
|---|---|---|---|
| v1 | "Fujifilm **Biotechnologies**"(2025년에 바꾼 새 이름)를 옛 이름 "후지필름 다이오신스"로 옮김 | 프롬프트 예시에 옛 이름 변환을 넣어 둠 | 예시 삭제, "제목에 쓰인 이름을 그대로" 규칙 |
| v2 | 같은 회사가 "후지필름"/"Fujifilm"으로 기사마다 섞이고, 알려진 회사도 영문으로 남음 | "한글 표기가 확실할 때만 한글"이라는 판단을 모델에 맡김 | **표기 목록 35개**를 프롬프트에 넣음: 목록에 있으면 그 표기, 없으면 영문 그대로 (v3) |
| v3 시험 | 통화가 없는 "4.3 billion"을 "43억 **달러**"로 옮김 | 금액 예시가 모두 달러였음 | "원제목에 없는 통화·단위는 붙이지 않는다" 규칙 |

- 결과: 797건 중 표기 목록 이름이 있는 237건 가운데 236건에 목록 표기를 적용했다. v1·v2 결과는 모두 지우고 v3로만 다시 번역했다.
- **교훈:** 예시는 규칙보다 강하게 작동한다. 일관성이 필요한 판단은 모델에 맡기지 말고 **목록으로 고정**한다.

### 2-7. 같은 사건이 다른 이름으로 나뉘었다 — 이슈 추출

| | 내용 |
|---|---|
| 문제 | 기사마다 따로 호출하니 같은 사건이 "삼성바이오로직스 폴리펩타이드그룹 인수" / "삼성바이오로직스 PPG 인수"처럼 다른 이름으로 나뉘었다 (이름 3,581개 중 3,301개가 기사 1건에만 붙음) |
| 대응 | 이름 목록만 보고 같은 사건을 대표 이름 하나로 합치는 묶기 단계를 따로 두었다 → 대표 이름 2,706개 |
| 남은 한계 | 묶기는 이름만 보고 판단하므로 다른 사건을 합칠(과병합) 위험이 있다. 묶은 뒤에도 대표 이슈 2,277개가 기사 1건짜리다. 표본 30건 검수에서 이름·유형·묶기 모두 97~99%였지만, 오류는 모두 **본문 있는 큰 묶음** 기사에서 나왔다: 인터뷰의 지엽적 한 구절("CDMO 진출")을 핵심 사건으로 잡아 6건짜리 묶음에 잘못 들어간 경우(I30), 식약처 주관 행사를 정책·규제로 둔 경우(I27) |

### 2-8. RAG — 검색이 약했고, 다른 대상의 사실을 답했다

| | 내용 |
|---|---|
| 문제 | 1차 검색 정확도 8/14. 사업·분기·반기보고서는 한 건이 최대 1,165개 청크라 색인을 채우고, 짧은 수시 공시(1~2청크)를 밀어냈다 |
| 대응 | 색인은 그대로 두고 사건성 공시(수주·증설·M&A 등)를 먼저 검색하는 자리 5개 + 전체 검색 2개로 바꿨다 → **12/14**. 근거 없는 질문 거절 6/6, 답변의 인용 구절이 실제 원문에 있는지 코드로 검증한다 |
| 환각 | 원문에 없는 수치를 지어낸 답은 찾지 못했다. 그러나 **질문한 대상과 다른 공시의 사실**을 답하는 경우가 남았다(같은 날 원공시를 정정 공시 대신 인용). 인용 검증은 "구절이 원문에 있는가"만 보므로 이 유형은 걸러내지 못한다 |
| 남은 한계 | 개선 값(자리 5개)을 평가 질문을 보고 정해 85.7%는 새 질문에서 낮을 수 있다. 질문 속 날짜·분기를 검색에 반영하지 못한다. 질문 20개를 시스템을 만든 사람이 직접 작성했다 |
| 교훈 | RAG의 환각은 "없는 말 지어내기"보다 **"맞는 문서의 틀린 대상"** 형태로 나타났다. 근거 표시와 거절만으로는 부족하다 |

### 2-9. 검수자가 LLM 답을 보면 끌려간다

| | 내용 |
|---|---|
| 문제 | 초기 이슈 검수(Claude 판정 50건)와 감성 정답 일부는 LLM 결과를 본 뒤 판정했다 |
| 대응 | 모달리티 검수는 LLM 태그를 가린 **블라인드 판정** 후, 엇갈린 7건만 다시 보고 최종 라벨을 정했다. 블라인드 판정만 쓰면 정밀도 88.3%, 재검토 후 최종 라벨로는 91.7%로 두 값을 함께 남겼다. 이슈 검수는 뽑은 코드가 없고 LLM 결과를 보며 판정한 옛 표본을 버리고, 재현할 수 있는 새 표본을 뽑았다 |
| 남은 한계 | 모달리티의 1차 판정자가 같은 계열 모델(Claude)이라, LLM과 같은 실수를 함께 했다면 일치한 73건 안에서는 드러나지 않는다 |

## 3. 공통으로 쓴 대응 방식

| 방식 | 왜 | 적용한 곳 |
|---|---|---|
| 사전 생성 + 저장 결과만 조회 | 가이드 6절. 화면이 느려지지 않고 결과가 고정된다 | T1~T4 전부 (공시 Q&A만 질문 시 호출) |
| dry-run → 20~50건 시험 → 전체 | 비용을 먼저 보고, 프롬프트 문제를 싸게 찾는다 | 모달리티(v1 문제 발견), 번역(v1·v3 문제 발견) |
| 결과에 모델·프롬프트 버전·시각 저장, 같은 버전 성공 건은 건너뜀 | 어떤 결과인지 추적하고, 끊겨도 이어서 실행 | T1~T4 |
| 구조화 출력 + 파서 검증 + 실패 사유 기록 | 형식 오류를 재시도 대상으로 남긴다 | T1~T4 |
| 층화 표본 + 층 가중 정확도 | 화면에 영향이 큰 층을 더 보면서 전체 수치는 편향 없이 | 감성, 모달리티, 이슈 |
| 판정 기준 문장화 → 갈린 건만 합의 | 일치도가 낮으면 정확도 숫자가 의미 없다 | 감성, 매칭, 모달리티 |
| 한계를 화면 문구로 공개 | 사용자가 결과를 과신하지 않게 | S2(감성 85%), S3(모달리티), S5(매칭), S6(RAG) |

## 4. 리포트 4절에 넣을 요약 (초안)

- **감성(영향) 분류:** CDMO 시장 전체의 파이를 기준으로 기회·위험·중립을 붙였다. 판단 규칙 11개를 두었고, 첫 단계는 "CDMO 관련성이 약하면 중립"이다. 사람 3명이 정한 정답 180건 기준 정확도는 85.0%로, 모두 기회로 찍는 기준선 47.2%보다 높다. 한계는 기사의 74%가 제목만으로 판단됐다는 점과, 정답 일부를 LLM 결과를 본 뒤 고쳤다는 점이다.
- **이슈 추출:** 기사마다 "주체 + 사건" 이름과 유형(8종)을 붙이고, 같은 사건의 다른 이름을 대표 이름으로 묶었다(3,581 → 2,706). 묶음이 클수록 화면에 보이므로 큰 묶음 위주로 표본 30건을 사람이 검수했고, 층 가중 정확 비율은 이름 98.7%, 유형 97.4%, 묶기 98.7%다. 다만 층 하나가 5~10건이라 경향으로만 본다.
- **모달리티 태깅:** PRD의 5종에 펩타이드·백신을 더한 7종이다. 펩타이드는 폴리펩타이드 인수, 백신은 SK바이오사이언스 주력 사업이라 추가했다. 표본 80건 기준 정밀도 91.7%, 재현율 98.1%이고, 오류는 주로 배경 언급을 태깅한 경우다.
- **영어 제목 번역:** 표기 목록으로 회사 이름을 고정해 797건을 번역했다. 원제목을 화면에 함께 보여 줘서, 번역 오류가 있어도 사용자가 바로 확인할 수 있다.
