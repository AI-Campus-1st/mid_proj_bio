## 1. 이 문서가 다루는 것

PRD **F5 뉴스-DART 공시 연계 및 AI 분석**(SQ4 "뉴스에 나온 변화가 실제 공시와 사업 활동으로 확인되는가")의 두 가지 작업을 정의한다.

| # | 작업 | 화면 (F5) | 스토리 · 검수 기준 | LLM 사용 |
|---|---|---|---|---|
| M1 | 뉴스-공시 매칭 | 이슈 ↔ 관련 공시 연결 목록 | US-15 · AC-15 | 없음 (규칙) |
| M2 | 공시 질의응답(RAG) | 공시 Q&A 창 | US-16, US-17 · AC-16, AC-17 | 임베딩 + 답변 생성 |

기업별 기사량 vs 공시 시점 차트(US-14 · AC-14)는 `v_company_daily` 를 그대로 그리면 되므로 이 문서에서 다루지 않는다.

두 작업의 역할은 다르다. **M1은 "어떤 공시를 볼지" 골라 주고, M2는 "그 공시에 뭐라고 적혀 있는지" 답한다.** 감성 분류(T1)가 뉴스의 영향 방향을 붙인다면, M1·M2는 그 뉴스에 **확인된 근거**를 붙인다 (PRD N6).

## 3. M1 뉴스-공시 매칭 규칙

### 3-1. 매칭 조건

세 조건을 모두 만족하면 연결한다.

| 조건 | 규칙 | 근거 |
|---|---|---|
| 같은 기업 | `news_companies.match_field IN ('title', 'body')` 인 기업과 `disclosures.corp_code` 가 같다 | PRD 4절: `query` 는 관련도가 낮아 기업 단위 분석에서 제외 |
| 시점 창 | 3-2절 | |
| 주제 대응 | 뉴스의 CDMO 키워드와 공시의 `event_class` 가 3-3절 표에서 대응한다 | 같은 기업·같은 시기라도 무관한 공시를 걸러낸다 |

중복 기사(`dup_of IS NOT NULL`)는 제외한다. 5개사가 언급되지 않은 기사(해외 CDMO, 정책 기사 대부분)는 매칭 대상이 아니다. 이 한계는 8절에 적는다.

### 3-2. 시점 창

| 창 | 범위 (기사 발행일 기준 공시 접수일) | 용도 | 상태 |
|---|---|---|---|
| 직접 | −3일 ~ +3일 | 같은 사건을 다룬 기사와 공시 | 데이터로 확인해 ±7일에서 줄임 (아래) |
| 후속 | +4일 ~ +90일 | "이 이슈 이후 실제 사업 활동이 있었나" 확인. 화면에서 직접 매칭과 구분해 표시 | **가설** (검증 전) |

**직접 창을 ±3일로 정한 근거** (2026-11-17, `data/db/bio_cdmo.sqlite` 2026-11-17 빌드 기준)

수주 공시 98건 각각에 대해 "접수일 ±N일 안에 같은 기업의 `CDMO 수주` 키워드 기사가 있는 비율"을 계산했다.

| 범위 | 원공시 49건 | 정정 공시 49건 |
|---|---|---|
| 당일 | 57% | 16% |
| ±1일 | 59% | 24% |
| ±3일 | 65% | 37% |
| ±7일 | 76% | 61% |
| ±14일 | 82% | 78% |
| ±30일 | 92% | 84% |

- 원공시는 절반 이상이 접수 당일에 기사가 나온다. 범위를 넓혀도 늘어나는 폭이 작다.
- ±7일로 실행했을 때 수주 직접 연결 711쌍의 날짜 차이 분포는 당일 152쌍, 그 외 14일은 하루 24~62쌍으로 평평했다. 삼성바이오로직스는 수주 기사가 거의 매일 나오므로, 당일에서 먼 연결은 같은 사건이 아니라 근처에 있던 기사일 가능성이 크다고 **추정**했다 (표본 검수 전).
- 기업별 차이가 크다. 원공시 기준 ±7일 포착률이 삼성바이오로직스·에스티팜 100%, 프레스티지바이오로직스 53%, SK바이오사이언스 33%, 바이넥스 25%이다. 기사량이 적은 기업의 공시는 창과 무관하게 기사가 없는 경우가 많다.

**실행 결과 비교** (대상 기사 2,849건, 사건성 공시 252건)

| 항목 | ±7일 | ±3일 |
|---|---|---|
| 직접 연결 | 1,581쌍 | 997쌍 |
| 후속 연결 | 5,812쌍 | 6,138쌍 |
| 전체 | 7,393쌍 | 7,135쌍 |
| 공시가 1건 이상 연결된 기사 | 1,562건 (54.8%) | 1,521건 (53.4%) |

이 표의 "기사"는 **기사 × 기업** 단위다 (`summarize()` 가 (`url`, `corp_code`) 쌍으로 센다). 여러 기업이 나온 기사는 기업마다 1건이라, 고유 기사(url)로 세면 대상 2,725건 · 연결 1,441건이다(±3일, 2026-11-19 확인). 대시보드 S5 지표도 기사 × 기업 단위를 쓴다 (UI_SPECIFICATION 미결 Q12 결정, 2026-11-19).

**남은 문제** — 창을 줄여도 풀리지 않았다.

- 전체 연결의 91%(6,469쌍)가 삼성바이오로직스이다.
- 2026년 삼성바이오로직스의 타법인 주식 취득 공시 몇 건에 `CDMO 경쟁 구도` 기사가 각각 300건 넘게 붙는다. 기사가 2026년에 몰려 있고 후속 창이 90일이기 때문이다.
- 후속 창(90일)과 공시당 연결 기사 수 제한은 표본 검수(6절) 결과를 보고 정한다.

### 3-3. CDMO 키워드 ↔ event_class 대응

| 뉴스 CDMO 키워드 | 직접 창에서 연결할 event_class | 후속 창에서 연결할 event_class |
|---|---|---|
| CDMO 수주 | 수주 | 수주, 실적 |
| CDMO 생산능력 | 증설, 자금조달 | 증설, 자금조달, 수주 |
| CDMO 경쟁 구도 | M&A·구조개편, 수주 | M&A·구조개편, 수주, 증설 |
| CDMO 모달리티 | 임상·허가·기술계약, 증설 | 임상·허가·기술계약, 증설, 수주 |
| CDMO 규제·정책 | (없음) | 수주, 증설, M&A·구조개편 |
| CDMO 지정학 | (없음) | 수주, 증설, M&A·구조개편 |

- 규제·정책과 지정학 기사는 공시와 **같은 사건**을 다루지 않으므로 직접 매칭을 하지 않고, 후속 창으로 "정책 이후 사업 활동"만 본다. 이는 선후 관계일 뿐 **인과를 뜻하지 않는다**는 문구를 화면에 둔다.
- `리스크` 공시는 키워드와 무관하게 같은 기업·직접 창이면 연결한다 (11건, 모두 삼성바이오로직스).
- 한 기사에 CDMO 키워드가 여러 개면(`news_cdmo_keywords`) 각 키워드의 대응을 합친다.
- `cdmo_kw_basis='query'` 기사는 연결하되 신뢰도 낮음으로 표시한다 (PRD 4절).

### 3-4. 정정 공시

`is_amended=1` 인 공시(154건, 수주 98건 중 49건)는 **제외하지 않고 "정정" 표시와 함께 연결**한다. 계약 금액·기간이 바뀐 최신 내용이 정정 공시에 있기 때문이다. 원공시와 정정 공시를 잇는 키는 현재 스키마에 없다(미확인). 같은 계약의 묶음이 필요해지면 `report_nm` 과 원문 속 계약 상대방으로 묶는 방법을 따로 정한다.

### 3-5. 정렬과 산출물

한 기사에 연결된 공시는 직접 창 → 후속 창, 그 안에서 **분류별 가중치**(`class_weight`) 높은 순 → 날짜가 가까운 순으로 정렬한다. 행의 `event_weight` 는 정정 공시이면 0이라, 그대로 쓰면 최신 내용이 담긴 정정 공시가 모두 뒤로 밀린다. 그래서 `analysis/disclosure_weights.py` 의 분류별 값(수주 5, 증설 4, M&A·구조개편 4, 실적 3, 임상·허가·기술계약 2, 자금조달 2, 리스크 0)을 쓴다.

결과는 미리 계산해 파일로 저장한다 (PRD N2). `news_id` 는 빌드마다 바뀔 수 있으므로 뉴스 키는 `url` 을 쓴다.

`data/processed/news_disclosure_links.csv` — `analysis/match_news_disclosure.py` 가 만든다 (기사 × 기업 × 공시 = 1행)

| 컬럼 | 설명 |
|---|---|
| `url`, `published_date` | 뉴스 키, 발행일 |
| `corp_code`, `corp_name` | 기업 |
| `rcept_no`, `rcept_date`, `report_nm` | 공시 키, 접수일, 보고서명 |
| `window` | `direct` / `follow` |
| `day_gap` | 공시 접수일 − 기사 발행일 (일) |
| `news_keyword` | 연결 근거가 된 CDMO 키워드 (여러 개면 `; ` 로 구분, 리스크 공시는 빈 값) |
| `event_class`, `class_weight`, `is_amended` | 공시 속성 |
| `kw_low_confidence` | `cdmo_kw_basis='query'` 이면 1 |
| `follow_cut` | 기사 발행일이 수집 기간 끝(2026-10-19)에서 90일 이내라 후속 창이 잘리면 1. "후속 공시 없음"이 아니라 "아직 알 수 없음"으로 읽는다 |

### 3-6. 이슈 단위로 올리기

화면 요구는 "**이슈** ↔ 관련 공시"인데, 이슈 추출(T2)은 아직 설계 전이다 ([AI_CLASSIFICATION](AI_CLASSIFICATION.md) 1절). 그래서 M1은 **기사 단위**로 먼저 만들고, 이슈 ID가 생기면 이슈에 속한 기사들의 연결을 합쳐 공시별 연결 기사 수로 정렬한다. T2가 늦어지면 CDMO 키워드 × 기업 × 월을 임시 이슈 단위로 쓴다.

## 4. M2 공시 RAG 구성

### 4-1. 흐름

```
[사전 생성]  disclosure_documents.text → 청킹 → 임베딩 → chromadb (chroma_db/)
[질의 시점]  질문 → 범위 확인 → 검색(필터 + 유사도) → 답변 생성 → 인용 검증 → 답변 또는 거절
```

색인(청킹·임베딩)은 미리 만들어 저장하고(PRD N2), 대시보드는 저장된 색인을 읽기만 한다. 질문은 사용자가 입력하므로 **질의 시점의 임베딩 1회와 LLM 호출 1회는 불가피**하다. PRD N1의 "대시보드에서 LLM 분류를 실시간으로 수행하지 않는다"와 충돌하지 않는 것으로 팀이 해석을 정했다 (7절 D4).

### 4-2. 청킹 기준

| 항목 | 기준 (가설) | 이유 |
|---|---|---|
| 대상 | `seq = 1` 본문. `seq ≥ 2` 첨부(감사보고서 등)는 1차에서 제외 | 파일 891개 중 첨부는 27개다(DB `seq ≥ 2` 집계로 확인, 2026-11-17). 첨부는 길고 질문과 거리가 멀다 |
| 분할기 | `langchain-text-splitters` 의 `RecursiveCharacterTextSplitter`, 구분자 `\n\n` → `\n` → 공백 | 원문은 태그를 제거한 텍스트이고 표는 행마다 줄바꿈되어 있어, 줄 단위로 자르면 표의 한 행이 중간에 끊기지 않는다 |
| 크기 | 1,000자, 겹침 150자 | 수주 공시의 계약 표(상대방·금액·기간)가 한 청크에 들어오는 크기로 가정 |
| 짧은 공시 | 1,000자 이하는 통째로 한 청크 | |
| 머리말 | 각 청크 앞에 `[기업명 | 보고서명 | 접수일]` 한 줄을 붙여 임베딩 | 청크만 떼어 놓으면 어느 회사의 어떤 공시인지 사라진다 |

표 처리: 표는 ` | ` 로 칸이 구분된 줄로 들어 있다. 표가 길어 청크가 나뉘면 뒤 청크에는 표 머리(열 이름)가 없다. 1차에서는 그대로 두고, 평가에서 표 관련 질문이 틀리면 표 머리 줄을 뒤 청크에 반복해 붙인다.

크기와 겹침은 평가 질문(6절)으로 500자·1,000자·1,500자를 비교해 확정한다. **1차 색인은 1,000자 / 겹침 150자로 만들었고 크기 비교는 하지 않았다** (`rag/build_index.py`, 공시 864건 → 청크 36,548개).

### 4-3. 임베딩 모델

팀의 LLM 호출은 현재 OpenAI API(`OPENAI_API_KEY`, `analysis/label_sentiment.py`)를 쓴다. 키를 하나로 유지하기 위해 **임베딩도 OpenAI 임베딩 모델을 쓴다** (팀 결정, 7절 D1). 한국어 공시와 한국어 질문이 대상이므로 다국어를 지원하는 모델이어야 한다. 모델 이름과 비용은 실행 시점에 확인해 이 절과 [AI_EVALUATION](AI_EVALUATION.md)에 기록한다.

**실행 기록 (2026-11-17):** `text-embedding-3-small`. 전체 색인에 29,194,290 토큰(글자당 0.85)을 썼고 가격표($0.02 / 100만 토큰) 기준 약 $0.58이다. 청구액은 콘솔에서 확인하지 않았다.

`requirements.txt` 에는 `langchain-anthropic` 만 있고 OpenAI용 LangChain 패키지가 없다. ~~구현할 때 `langchain-openai` 를 버전을 고정해 추가한다.~~ **구현에서는 추가하지 않았다.** 임베딩과 답변 호출은 `openai` SDK 를 직접 쓰고(토큰 사용량 기록·재시도 제어), 단계 연결에만 `langchain-core` 의 Runnable 을 쓴다. `requirements.txt` 는 바뀌지 않았다.

### 4-5. 검색

1. **범위 확인** — 질문에 5개사가 아닌 기업명이 있으면 검색하지 않고 거절한다 (AC-17 "범위 밖 기업"). 기업명 판별은 `collect/config.py` 의 `COMPANY_PATTERNS` 를 재사용한다.
2. **필터** — 대시보드 공통 필터(F7)의 기업·기간과 질문에서 찾은 기업명을 chromadb `where` 조건으로 건다.
3. **유사도 검색** — 후보 20개를 가져와, 같은 공시(`rcept_no`)에서는 상위 2개 청크까지만 남기고 최종 5개를 답변에 넘긴다 (모두 가설).
   - **구현 변경 (2026-11-17):** 위 방식은 평가에서 검색 정확도가 8/14였다. 사업·분기보고서와 증권신고서 청크가 짧은 수시 공시를 밀어냈기 때문이다. 지금은 **사건성 공시 7종만 검색해 5개 + 전체 검색에서 2개 = 최대 7개**를 넘긴다(검색마다 후보 20개, 공시당 2개까지). 같은 질문에서 12/14가 됐다. 자리 수는 평가 질문을 보고 정한 값이다 ([AI_EVALUATION](AI_EVALUATION.md) 6절).
4. **정정 우선** — 같은 보고서명의 원공시와 정정 공시가 함께 걸리면 접수일이 늦은 것을 앞에 둔다.

### 4-6. 답변 체인

LangChain으로 `검색기 → 프롬프트 → LLM → 출력 파서` 를 잇는다. 답변 LLM은 감성 분류와 같은 모델을 쓴다 (팀 결정, 7절 D2).

프롬프트 규칙:

- 주어진 공시 발췌에 **적힌 내용만으로** 답한다. 발췌에 없는 수치·날짜·상대방을 추측하지 않는다.
- 답의 각 문장에 근거 공시의 `rcept_no` 를 붙인다.
- 발췌로 답할 수 없으면 `refused: true` 로 답한다.
- 투자 판단·전망을 묻는 질문에는 공시에 적힌 사실만 전하고 판단은 하지 않는다.

출력 형식 (JSON):

```json
{
  "refused": false,
  "answer": "답변 본문",
  "citations": [
    {"rcept_no": "…", "quote": "근거가 된 원문 구절"}
  ],
  "refusal_reason": null
}
```

`report_nm`·`rcept_date`·`url` 은 LLM이 쓰게 하지 않고 **코드가 `rcept_no` 로 메타데이터에서 채운다.** LLM이 링크나 날짜를 지어내는 것을 막기 위해서다.

### 4-7. 거절 기준

아래 중 하나라도 해당하면 답변 대신 거절 문구를 보여준다 (PRD F5 필수 조건, AC-17).

| 단계 | 거절 조건 | 예 |
|---|---|---|
| 검색 전 | 5개사가 아닌 기업에 대한 질문 | "론자의 2025년 수주는?" |
| 검색 후 | 최상위 청크의 유사도가 임계값 미만 | 공시와 무관한 질문 |
| 생성 후 | LLM이 `refused: true` 로 답함 | 존재하지 않는 계약을 묻는 질문 |
| 검증 | `citations` 가 비었거나, 인용한 `rcept_no` 가 검색된 청크에 없음 | LLM이 근거를 지어낸 경우 |
| 검증 | `quote` 가 해당 청크 원문에 없음 (공백 정규화 후 비교) | 인용 구절 환각 |

유사도 임계값은 임베딩 모델에 따라 달라지므로 **미정**이다. 평가 질문(6절)의 답 있는 질문과 거절 질문의 점수 분포를 보고 정한다.

**평가 결과 (2026-11-17): 임계값을 적용하지 않는다.** 최상위 유사도가 답 있는 질문 0.56~0.74, 거절해야 하는 질문 0.37~0.61로 겹쳐 값 하나로 가를 수 없었다. 그래서 표의 "검색 후" 단계는 지금 "조건에 맞는 공시가 하나도 없을 때"만 동작하고(`rag/qa.py` 의 `MIN_SIMILARITY = 0`), 근거 없는 질문의 거절은 생성 후·검증 단계가 맡는다. 평가의 거절 6건 중 5건이 생성 후 단계였다.

범위 밖 기업은 `rag/qa.py` 의 `OTHER_COMPANIES` 목록(비교 대상 9개사와 주요 CDMO·제약사 이름)으로 판별한다. 목록에 없는 기업은 검색 전에 걸러지지 않고 뒤 단계에서 거절된다.

거절 문구(안): "수집한 5개사 공시(2023-10-19 ~ 2026-10-19)에서 근거를 찾지 못해 답변하지 않습니다."

### 4-8. 근거 표시 형식

답변 아래에 인용한 공시를 표로 보여준다 (AC-16: 공시명·제출일·DART 링크).

| 기업 | 공시명 | 제출일 | 근거 구절 | 링크 |
|---|---|---|---|---|
| `corp_name` | `report_nm` (정정이면 "정정" 표시) | `rcept_date` | `quote` | `url` |

**대시보드용 반환값 (2026-11-18, UI_SPECIFICATION 미결 Q3 대응).** `rag/qa.py` 의 `ask()` 는 기존 키를 그대로 두고 아래를 추가했다.

| 키 | 내용 |
|---|---|
| `answer_display` | 답변의 `(접수번호)` 를 근거 번호 `[1]`, `[2]` 로 바꾼 화면용 문장. 같은 공시는 같은 번호. 인용 목록에 없는 접수번호가 섞인 괄호는 바꾸지 않는다 |
| `citations[].n` | 위 번호. 같은 공시를 여러 번 인용하면 한 항목으로 합치고 구절은 `quotes` 에 모은다 (`quote` 는 첫 구절) |
| `flags` | `judgment_declined`(투자 판단을 요구한 질문이라 판단하지 않음), `causality_unconfirmed`("인과는 공시로 확인되지 않는다"를 덧붙임). LLM 출력 스키마에 넣어 문구 검색 없이 판정한다 |
| 오류 | 키·색인이 없거나 API 호출이 실패하면 프로그램을 끝내지(`sys.exit`) 않고 `QAError` 를 던진다. `code` 는 `no_api_key` / `no_index` / `api_error`. 근거가 없어 답하지 않는 경우는 지금처럼 `refused` 로 돌려준다 |

범위 밖 안내 문구의 5개사 순서는 INFORMATION_ARCHITECTURE 4-1절 순서로 맞췄다 (Q10).

## 8. 한계

- **5개사 공시만 있다.** 해외 CDMO나 정책 기사처럼 5개사가 언급되지 않은 기사는 공시와 연결되지 않는다. 뉴스 9,216건 중 기업 매핑이 있는 기사만 M1 대상이다.
- **시점이 가깝다고 인과는 아니다.** 후속 창 연결은 "이후에 이런 공시가 있었다"는 선후 관계만 보여준다.
- **CDMO 키워드는 규칙 기반 분류이고 정확도를 검수하지 않았다** (`docs/news_sort.md` 5절). 주제 대응의 정확도는 여기에 묶인다.
- **`event_class` 는 보고서명 정규식 분류다** (`analysis/disclosure_weights.py`). `임상·허가·기술계약` 은 "투자판단관련주요경영사항" 전체를 받으므로 내용이 섞여 있다.
- **공시는 의무 공시 범위만 담는다.** 공시 기준 금액에 못 미치는 계약이나 상대방 비공개 계약은 원문에 내용이 없어, 뉴스에는 있지만 RAG는 거절하는 경우가 생긴다.
- **표가 청크 경계에서 나뉘면** 열 이름이 빠져 숫자의 의미를 잃을 수 있다 (4-2절).
- **원문 없는 공시 3건**은 RAG로 답할 수 없다.
- **`data/db/` 와 `chroma_db/` 는 git에 없다.** 팀원마다 DB와 색인을 직접 만들거나 전달받아야 하고, 빌드 시점이 다르면 결과가 달라질 수 있다.
