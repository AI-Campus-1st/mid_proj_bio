## 3. 처리 범위와 근거 (가이드 6절)

| 기능 | 대상 | 입력 | 근거 |
|---|---|---|---|
| T1·T2·T3 | **대표 CDMO 키워드가 있는 중복 제외 기사 4,727건** (전체 9,142건 중) | 제목 + 본문 앞 1,500자, 본문이 없으면 제목만 | CDMO와 무관한 기사(`해당 없음` 4,487건)는 기회/위험·이슈·모달리티를 판단할 의미가 없다. 기사 핵심은 대개 앞부분에 있어 1,500자로 호출량·비용을 줄인다. 세 기능이 같은 기사 집합이라 URL로 붙는다 |
| | → 제목만 3,505건(74%), 제목 + 본문 1,222건 | | 구글 뉴스 수집분은 본문이 없다. 본문 크롤링은 하지 않기로 함([DECISIONS](../07_project-management/DECISIONS.md) D-09). 결과마다 `input_basis` 를 저장하고 정확도를 입력 범위별로 나눠 본다 |
| T2-b | T2가 만든 이슈 이름 목록 3,581개 (기사가 아니라 이름만) | 이름 120개씩 + 이미 정한 대표 이름 250개 | 기사를 다시 넣지 않아 호출량이 작다 |
| T4 | 영어 기사(`lang='en'`) 797건 전부 | 제목 한 줄 | 본문이 없고 건수가 작아 전부 처리 |
| R1 색인 | 원문 있는 공시 864건 전부의 본문(`seq=1`) | 1,000자 청크, 겹침 150자 → 36,548개 | 질문이 어느 공시를 물을지 모르므로 전체. 첨부(감사보고서 등)는 뺐다 |
| R1 질의 | 질문 1개 | 질문 임베딩 1회 + 발췌 최대 7개로 답변 1회 | 5절 |

**표본 추출로 줄이지 않은 이유:** 대시보드는 기간·기업·카테고리 필터로 거른 모든 기사에 라벨을 보여 줘야 한다(필터가 모든 차트에 반영). 그래서 분류는 범위 안 전체를 처리하고, 정확도 확인에만 표본을 쓴다.

## 4. 사전 생성 원칙과 저장 위치 (PRD N1·N2)

| 기능 | 결과 파일 (`data/processed/`) | 키 | 대시보드가 하는 일 |
|---|---|---|---|
| T1 | `sentiment_llm.csv` | `url` | 읽고 붙이기 |
| T2 | `issues_llm.csv` | `url` | (S0 카드 생성에 사용) |
| T2-b | `issue_groups.csv` | `issue_norm` | (같음) |
| T3 | `modality_llm.csv` | `url` | 읽고 붙이기 |
| T4 | `title_ko.csv` → DB `news.title_ko` | `url` | DB에서 읽기 |
| R1 색인 | `chroma_db/` (git 제외) | 청크 ID, `rcept_no` | 질문할 때 검색 |
| 요약 | `summary_cards.json` | 카드 ID | 읽고 필터로 거르기 |

- 모든 LLM 단계는 **이미 같은 모델·프롬프트 버전으로 성공한 행을 건너뛰고**, 일정 건수마다 중간 저장한다. 끊겨도 같은 명령으로 이어서 처리하고, 비용은 새 행에만 든다.
- 프롬프트 버전(`prompt_version`)과 모델을 결과 행마다 저장한다. 버전이 바뀌면 섞이지 않게 전체를 다시 처리한다 (감성 v1→v2→v3 때 그렇게 했다).
- 결과를 DB가 아니라 파일로 두는 이유는 [DATABASE_SCHEMA](../06_technical/DATABASE_SCHEMA.md) 5절.
- **예외는 공시 Q&A의 질문 시점 호출 하나다** ([DECISIONS](../07_project-management/DECISIONS.md) D-22).

## 5. RAG 필수 조건

| 조건 (가이드 6절) | 구현 | 확인 |
|---|---|---|
| 답변에 근거 공시(공시명, 제출일, 링크) 표시 | 답변의 근거 번호 `[1]`, `[2]` 와 근거 공시 목록(공시명·제출일·기업·DART 링크·인용 구절). 공시명·제출일·링크는 LLM이 아니라 색인 메타데이터에서 채운다 | AC-16 통과 (대시보드 S6) |
| 근거가 확인되지 않으면 거절 | 3중 거절: ① 5개사 밖 기업 질문은 검색 전 거절 ② LLM이 발췌로 답할 수 없다고 판단하면 거절 ③ 인용한 접수번호·구절이 실제 발췌에 없으면 거절 | 평가 20문항: 거절 정확도 6/6, 잘못된 거절 1/14 |
| (추가) 투자 판단을 하지 않는다 | "사야 하나?" 같은 질문은 판단하지 않고 공시 사실만 안내 (`flags.judgment_declined`) | 화면 안내 문구 |
| (추가) 인과를 단정하지 않는다 | 정책·뉴스와 공시 사이 인과는 확인되지 않는다고 덧붙임 (`flags.causality_unconfirmed`) | 화면 안내 문구 |

입출력 형식은 [API_SPECIFICATION](../06_technical/API_SPECIFICATION.md) 4절.

| 기능 | 모델 | 호출량 | 비용 (기록된 값) |

- 모든 비용은 가격표와 토큰 수로 계산한 **추정**이고 OpenAI 콘솔 청구액은 확인하지 않았다. 가격표: `gpt-6-luna` 입력 $0.10 · 출력 $0.50, 임베딩 $0.02 (100만 토큰당, 코드의 `PRICE` 표).
- 모든 LLM 스크립트에 `--dry-run`(호출 없이 건수·예상 비용 출력)이 있고, **실행 전에 비용을 추정해 팀 승인을 받는다** (팀 작업 방식).
- 모델 선택 이유와 대안은 [TECH_STACK](../06_technical/TECH_STACK.md) 5절, [DECISIONS](../07_project-management/DECISIONS.md) D-16·D-21.
