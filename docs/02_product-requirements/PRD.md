## 2. 기능 요구사항

기능 번호(F1~F6)는 [USER_STORIES](USER_STORIES.md)와 [ACCEPTANCE_CRITERIA](ACCEPTANCE_CRITERIA.md)에서 그대로 쓴다. 우선순위: **P0** 과제 필수 / **P1** 핵심 질문에 필요 / **P2** 선택.

### F1. 핵심 이슈 및 뉴스 트렌드 — 산업 동향 / SQ1

| 항목 | 내용 |
|---|---|
| 우선순위 | P0 |
| 답하는 질문 | 지금 가장 중요한 이슈는 무엇이고, 무엇이 새로 부상하고 있는가 |
| 화면 구성 | 월별 기사량 추이(중복 제외), 이슈 급증 시점 표시, 기간별 상위 이슈 목록, 이슈별 대표 기사 |
| 분석 방법 | 기사량 시계열 + 변화점 탐지(`ruptures`), LLM 이슈 추출로 기사를 이슈 단위로 묶음, 직전 기간 대비 증가율로 "부상 이슈" 판정 |
| 데이터 | `news` (`dup_of IS NULL`), `news_cdmo_keywords` (CDMO 키워드 6개), `news_keywords.category`, `cdmo_mention` |

### F2. 규제·정책 모니터링 — 정책·규제 / SQ2

| 항목 | 내용 |
|---|---|
| 우선순위 | P1 |
| 답하는 질문 | 어떤 정책·규제 변화가 있었고, CDMO 산업에 기회인가 위험인가 |
| 화면 구성 | 정책·규제 이슈 타임라인, 이슈별 감성(기회/위험) 분류, 관련 기업 언급 |
| 분석 방법 | `규제 및 정책` 카테고리 기사(CDMO 규제·정책, CDMO 지정학)에 LLM 감성·영향 분류 |
| 데이터 | `news_cdmo_keywords` (`category='규제 및 정책'`), 해외(영어) 지정학 뉴스(`origin='google_global'`) — 화면에는 한국어 번역(`title_ko`) 표시 |

### F3. 기술·생산능력 분석 — 기술·생산 / SQ2

| 항목 | 내용 |
|---|---|
| 우선순위 | P1 |
| 답하는 질문 | 어떤 모달리티(항체, ADC, mRNA, 세포·유전자치료제, 올리고 등)와 생산기술이 성장하며, 기업은 어떻게 대응하는가 |
| 화면 구성 | 모달리티별 언급 추이, 기업 × 모달리티 히트맵, 증설 공시 목록 |
| 분석 방법 | LLM으로 기사·공시에서 모달리티·생산기술 태그 추출 |
| 데이터 | `news_cdmo_keywords` (CDMO 모달리티, CDMO 생산능력), `disclosures` (`event_class='증설'`), `disclosure_documents` 원문 |

### F4. 기업별 비교 및 경쟁사 분석 — 시장·경쟁 / SQ3

| 항목 | 내용 |
|---|---|
| 우선순위 | P1 |
| 답하는 질문 | 기업별 수주·생산시설 투자·경쟁 구도는 어떻게 변하고 있는가 |
| 화면 구성 | 5개사 수주·증설·M&A·자금조달 공시 건수 비교, 기업별 공시 타임라인, 수주 계약 금액 추이 |
| 분석 방법 | `event_class` 기준 집계, 수주 공시 원문에서 계약 금액·상대방 추출 |
| 데이터 | `disclosures` (`event_class`, `event_weight`), `disclosure_documents`, `v_company_daily` |

### F5. 뉴스-DART 공시 연계 및 AI 분석 — 근거·의사결정 / SQ4

| 항목 | 내용 |
|---|---|
| 우선순위 | P0 (공시 Q&A는 과제 필수) |
| 답하는 질문 | 뉴스에 나온 변화가 실제 공시와 사업 활동으로 확인되는가, 그 근거는 무엇인가 |
| 화면 구성 | 기업별 기사량 vs 공시 시점 비교 차트, 이슈 ↔ 관련 공시 연결 목록, 공시 질의응답(RAG) 창 |
| 분석 방법 | 같은 기업·인접 시점의 뉴스와 공시 매칭, 공시 원문 기반 RAG 답변 + 출처 링크 |
| 데이터 | `v_company_daily`, `v_documents`, `disclosure_documents.text`(RAG 원천), `disclosures.url`(근거 링크) |
| 필수 조건 | 답변에 근거 공시(공시명, 제출일, 링크) 표시. 근거가 확인되지 않는 질문에는 답변 거절 |

### F6. 요약 — 기회와 위험 요인 / SQ5, Core Question

## 3. 비기능 요구사항

| # | 요구사항 | 출처 |
|---|---|---|
| N1 | **계층 분리.** 수집·분석·대시보드를 분리하고, 대시보드에서 API를 직접 호출하거나 LLM 분류를 실시간으로 수행하지 않는다 | 가이드 6절 |
| N2 | **사전 생성.** LLM 분석 결과·번역·임베딩은 미리 생성해 저장하고, 대시보드는 조회만 한다 | 가이드 6절 |
| N3 | **LLM 결과 검증.** 감성 분류·이슈 추출은 표본 검수로 정확도를 확인해 기록한다. 처리 범위(제목 기준, 표본 추출 등)와 근거도 기록한다 | 가이드 6절 |
| N4 | **재현성.** 수집 코드는 재실행 가능해야 하고, 수집 기간은 뉴스와 정렬한다. README에 실행 순서를 적는다 | 가이드 2-4·7·8절 |
| N5 | **보안.** DART·LLM API 키는 `.env` 로 관리하고 `.gitignore` 에 등록한다. 코드·저장소·발표자료에 키를 노출하지 않는다 | 가이드 6절 |
| N6 | **근거 표시.** 모든 이슈·요약 문장에 출처를 붙이고, 근거 없는 LLM 결과는 노출하지 않는다 | 제품 원칙 |
| N7 | **실행 환경.** 로컬에서 Streamlit으로 실행 가능하거나 배포 URL을 제공한다 | 가이드 7절 |

## 4. 데이터 해석 규칙

| 규칙 | 이유 |
|---|---|
| 기사량은 중복(`dup_of`)을 제외하고 센다 | 같은 기사의 전재·재송고로 기사량이 부풀려짐 |
| 기업 단위 분석은 `match_field IN ('title', 'body')` 만 쓴다 | `query` 는 기업명 검색에 걸렸지만 제목에 기업명이 없는 기사로 관련도가 낮음 |
| 본문 기반 분석(감성 등)은 본문이 있는 출처(`provided`, `team`) 범위임을 화면에 표시한다 | 구글 뉴스 수집분은 제목만 있음 |
| `cdmo_kw_basis='query'` 기사는 신뢰도가 낮음을 감안한다 | 제목에 단서가 없어 검색어를 따른 분류 |
| 기사량 추이는 `origin` 별로 나눠 해석한다 | 팀원 수집·CDMO 검색은 2026년에 몰려 있음 |

## 5. 제약과 한계

| 한계 | 영향받는 기능 | 대응 |
|---|---|---|
| 뉴스가 국내 언론 중심 | F1, F2 ("글로벌" 동향) | 지정학 이슈는 해외(영어) 뉴스 797건으로 보강함. 다른 이슈는 국내 언론 중심임을 화면에 명시 |
| 분석 기업이 국내 상장 5개사 | F4 (글로벌 경쟁 구도) | 론자·우시 등 해외 CDMO는 뉴스 언급으로만 다루고, 공시 비교는 5개사로 한정 |
| 모달리티·생산기술 분류 컬럼이 DB에 없음 | F3 | CDMO 모달리티 키워드로 1차 구분, LLM 태깅 결과를 별도 테이블로 적재 |
| 구글 뉴스 수집분은 본문이 없음 | F1, F2 (감성·이슈 추출) | 본문 분석은 제공·팀원 수집 뉴스로, 나머지는 제목 기반으로 범위를 나눔 |
| 산업 보고서·경쟁사 홈페이지는 수집 대상이 아님 | 페르소나의 정보 탐색 일부 | 뉴스·공시로 한정하고 화면에 명시 |
| CDMO 키워드 분류는 규칙 기반이며 정확도 미검수 | F1~F3 | 표본 검수 후 정확도 기록 (`04_ai/AI_EVALUATION.md`) |
| 공시 건수는 금액이 아님 | F4 | 수주 공시 원문에서 계약 금액 추출로 보완 |
