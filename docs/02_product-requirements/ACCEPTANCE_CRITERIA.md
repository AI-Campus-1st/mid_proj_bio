## 2. 사용자·질문 반영

- [ ] 첫 화면에서 Core Question에 대한 답(기회·위험 요약)을 바로 볼 수 있다
- [ ] 영역별 핵심 질문 5개가 각각 하나 이상의 화면으로 답해진다 (F1~F5)
- [ ] Supporting Questions 5개가 각각 하나 이상의 화면으로 답해진다
- [ ] Pain Point P1~P4가 각각 해당 기능으로 해소된다
- [ ] 대표 사용 시나리오를 처음부터 끝까지 대시보드 안에서 수행할 수 있다
- [ ] 처음 보는 사람이 결론을 이해할 수 있다 (과제 Day 7 확인 사항)

## 3. 근거 제시

- [ ] 모든 이슈·요약 문장에 출처(뉴스 URL 또는 DART 링크)가 붙어 있다
- [ ] RAG 답변은 공시 원문에서 찾은 근거와 링크를 함께 보여준다
- [ ] 근거가 연결되지 않은 LLM 결과는 요약 카드에 노출하지 않는다

## 4. 데이터 해석

- [ ] 기사량은 중복(`dup_of`)을 제외하고 센다
- [ ] 기업 단위 분석은 `match_field IN ('title', 'body')` 만 쓴다
- [ ] 본문 기반 분석(감성 등)은 본문이 있는 출처(`provided`, `team`) 범위임을 화면에 표시한다
- [ ] 해외 뉴스는 지정학 이슈만 보강되었음을 화면에 표시한다

## 5. 과제 제출 전 점검 (가이드 8절)

- [ ] 공시 수집 코드가 재실행 가능하며, 수집 기간이 뉴스와 정렬되어 있다
- [ ] 대시보드가 API를 직접 호출하지 않고 저장된 결과를 조회한다
- [ ] LLM 분류 결과를 표본 검수하고 정확도를 기록하였다
- [ ] 공시 Q&A 답변에 근거 공시가 표시된다
- [ ] 필터가 모든 차트에 반영된다
- [ ] 대시보드에 결론이 명시되어 있다
- [ ] 키가 저장소와 발표자료에 포함되지 않는다
- [ ] 조원 모두 전 과정의 설계 판단을 설명할 수 있다
